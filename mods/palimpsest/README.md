# Palimpsest

Palimpsest is an experimental client mod for historical map storage. This first version contains a synthetic storage benchmark. It does not read chunks or render an actual map. The headless suite tests color distributions from uniform and near-uniform tiles through bands, varied colors, solid footprints, and scattered edits. It reports stored bytes against the previous plain encoding, one-pixel sample bytes and timing, and verifies every tile before and after each edit. These deterministic patterns approximate possible map colors; actual chunk colors still need a separate capture test.

Run `/palimpsest` in game to open the benchmark. **Sparse +250** creates a 32×32 tile world and adds 250 time steps with eight changed cells per edited tile. **Mixed +250** appends overlapping rectangles, scattered changes, and occasional full-tile edits. **Stress +1000** repeatedly changes one cell per edited tile, deliberately leaving long histories to traverse. All three can extend an existing history. **Checkpoint all tiles** appends one full-coverage layer per tile at the next epoch. **Auto** checkpoints only the most expensive tiles in the latest visible viewport when the configurable layer-visit budget is exceeded; it starts off, so enabling it is an explicit action. Scrub the slider to reconstruct an earlier view, pan the 8×6 viewport, and use **Reopen index** to time a full disk scan. **Probe 120 reads** reports median, p95, and maximum warm-cache read times for the selected viewport and epoch. **Run diagnostics + checkpoint visible tiles** measures the latest viewport, appends checkpoints for its visible tiles, measures the same pixels again, reopens the index, and measures once more. Its log is written under `config/palimpsest/benchmark/reports/`, and the full path appears in the GUI.

The storage workload suite is headless and needs no game: `./gradlew -p mods/palimpsest storageSuite` creates temporary sparse, mixed, and adversarial histories, including a million-layer stress case and a dense 512×512-tile world plus distant observed tiles; checks no-op rejection and pixel integrity; measures reads before and after checkpointing and index rebuilds; prints the report and saves it under `build/palimpsest/reports/`. It lives in the `benchmark` source set and is not part of the mod jar. The readout also reports sealed bytes, layers visited, and layers decoded; writes report covered cells and bytes added.

**Paged view** renders the same synthetic history as 128×128 GPU images. Its camera pans across empty space and zooms through LOD 0–12. Page images remain stable while the camera moves, so moving and zooming change draw commands without rebuilding unchanged pixels or Compose layout. Derived pages are built on an IO worker. The latest view has a bounded page cache, and time travel keeps one bounded historical working set. Moving through time checks the tile/time index, rereads only tiles with changed layers in cached pages. New observations invalidate the affected latest pages. The framework clips GPU drawing to the canvas bounds.

For the future world map, `MapPageStore` partitions tile histories into 32×32-tile region directories and keeps at most 256 region indexes open by default. It couples appends with page-cache invalidation. Reads take shared locks, so page builds on different regions run in parallel and never block an append; a page is built outside the cache lock and simply not cached if one of its tiles changed meanwhile. An append validates every region's batch before sealing the first segment. New layers drop the latest pages of their tiles; historical pages are dropped only when a new layer's epoch is at or before the pinned historical epoch, which keeps time scrubbing warm while chunks keep being observed. The benchmark keeps its existing flat history folder so earlier benchmark data remains usable. Derived LOD images are not persisted or Git-synced yet. Each zoomed-out pixel uses one deterministic source pixel instead of averaging a block; at LOD 4, one pixel represents an entire tile. Farther levels sample one tile from increasingly wide world areas and reduce page reads from 16,384 to 4,096, 1,024, then 256. The 128×128 page repeats those samples across larger cells; sample positions stay anchored to world coordinates. The horizontal suite measures page footprint, reads, bytes, latency, region reopen counts, and allocated index arrays at LOD 4–12 with 16- and 256-region caches, both with and without a local disk index. The storage reader uses index masks to find the layers covering requested pixels and issues positioned reads for their color bytes. The suite reports logical record bytes transferred; actual disk I/O still depends on filesystem and OS caching.

Each tile is 16×16 pixels with one byte per color. Every observation is the same layer type: a time stamp, a 256-bit coverage mask, and colors for its covered pixels. A first observation covers all pixels. Later observations usually cover only changed pixels. The codec stores sparse changes as position/color pairs, larger changes with a mask, and full tiles as colors. Full tiles and larger masks whose covered pixels all share one color store that color once. Full tiles with up to 16 exceptional pixels store a dominant color plus sorted position/color exceptions. Sampled reads still use one positioned read per contributing layer; exception records need the whole short record to locate an exceptional pixel. Historical reads walk layers from newest to oldest and skip a layer when newer layers already cover all its pixels. The suite includes a structured-color fixture comparing flat tiles and uniform patches with varied tiles; it is synthetic, not evidence of actual-world compression.

Before an append, Palimpsest compares every covered pixel with the latest stored tile. Matching pixels are removed from ordinary layers; a layer with no changed pixels creates no record or segment. `TileLayer.full` is a full observation subject to that rule. `TileLayer.snapshot` explicitly keeps a complete layer even when every pixel is unchanged, for checkpointing. The distinction affects the append decision only; both use the same on-disk layer format.

Layers land first in a local write-ahead log (`.pending.wal`, checksummed frames, fsynced per append) and are sealed into one immutable, content-addressed `.pseg` segment once the log reaches 1 MiB or five minutes, on flush, and on close. A crash replays the log on the next open and truncates a damaged tail. Segments group records by tile, store epochs as per-tile deltas, and choose sparse position/color pairs, a coverage mask, or full colors for each layer. Each record describes its own length through its encoding and coverage. Segment names are SHA-256 hashes of their content, so a directory synced through Git merges as a plain union of files. `compact()` merges small segments (under 4 MiB) once eight of them exist, deleting the inputs; because each machine may do that independently, a reader tolerates the same layer arriving from two segments and keeps one deterministically — the copy from the segment whose name sorts first — so every machine resolves a merge identically. Epochs are meant to be wall-clock milliseconds of the observation: they need no coordination between machines and are what a time-lapse wants. The store writes a `.gitignore` covering logs, sidecars and temp files; only `.pseg` files are map data. On reopening, Palimpsest verifies each segment's SHA-256 name once per process; a segment whose size and modification time are unchanged since that check is trusted on later opens, so region eviction and reopening do not rehash. It loads a disposable `.index-cache.pidx` record directory when one matches the exact segment set, or parses every record to rebuild the index when it does not. Sealing writes a temporary file before an atomic rename and re-points the affected tiles' index entries from the log to the new segment.

The in-memory index packs, per layer, one epoch, one word holding segment ID, record position, length and encoding kind, and one coverage reference into primitive arrays per tile. A one-pixel layer stores its pixel position directly; two to eight pixels fit in one packed side-array entry; a full layer uses a sentinel; larger masks use a separate side array. Tile histories dominated by large masks switch to inline masks when that uses less memory. A combined mask for every 64 layers can skip a whole group when newer layers already resolve all of its pixels. Sampled reads derive color offsets from indexed coverage and record length, so they need one positioned read per contributing layer without fetching its header. The GUI's **index arrays** figure counts the arrays of currently resident tiles; it excludes object overhead, file channels, the sidecar mapping, and the rest of the game heap. The disposable index avoids reparsing layer records. Its disk format holds a segment list, one checksummed record block per tile using epoch deltas, variable-length numbers and compact coverage masks, and a tile directory with each tile's record count and newest epoch. Opening a region reads only the directory; a tile's block is loaded when the tile is first read, and clean tiles beyond a per-region resident budget (16 MiB by default) are evicted least-recently-used. Tiles appended since the last save stay resident until the sidecar is rewritten, which copies untouched blocks byte for byte. The sidecar is written atomically whenever a store with at least 256 layers is flushed or closed; smaller regions are parsed directly because that is cheaper than a sidecar. The sidecar is ignored by Git and must not be synced as map data; deleting it only makes the next open rebuild it.

The benchmark uses reproducible random edits. It measures the storage prototype on your machine; it is not a gameplay performance result.
