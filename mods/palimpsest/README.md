# Palimpsest

Palimpsest is an experimental client mod for historical map storage. This first version contains a synthetic storage benchmark. It does not read chunks or render an actual map.

Run `/palimpsest` in game to open the benchmark. **Sparse +250** creates a 32×32 tile world and adds 250 time steps with eight changed cells per edited tile. **Mixed +250** appends overlapping rectangles, scattered changes, and occasional full-tile edits. **Stress +1000** repeatedly changes one cell per edited tile, deliberately leaving long histories to traverse. All three can extend an existing history. **Checkpoint all tiles** appends one full-coverage layer per tile at the next epoch. **Auto** checkpoints only the most expensive tiles in the latest visible viewport when the configurable layer-visit budget is exceeded; it starts off, so enabling it is an explicit action. Scrub the slider to reconstruct an earlier view, pan the 8×6 viewport, and use **Reopen index** to time a full disk scan. **Probe 120 reads** reports median, p95, and maximum warm-cache read times for the selected viewport and epoch. **Run diagnostics + checkpoint visible tiles** measures the latest viewport, appends checkpoints for its visible tiles, measures the same pixels again, reopens the index, and measures once more. **Run standalone storage suite** needs no existing history: it creates temporary sparse, mixed, and adversarial histories, including a million-layer stress case and a dense 512×512-tile world plus distant observed tiles; checks no-op rejection and pixel integrity; and measures reads before and after checkpointing and index rebuilds. The suite can be stopped after its current generation batch. Both logs are written under `config/palimpsest/benchmark/reports/`, and the full path appears in the GUI. The readout also reports sealed bytes, layers visited, and layers decoded; writes report covered cells and bytes added.

**Paged view** renders the same synthetic history as 128×128 GPU images. Its camera pans across empty space and zooms through LOD 0–12. Page images remain stable while the camera moves, so moving and zooming change draw commands without rebuilding unchanged pixels or Compose layout. Derived pages are built on an IO worker. The latest view has a bounded page cache, and time travel keeps one bounded historical working set. Moving through time checks the tile/time index, rereads only tiles with changed layers in cached pages. New observations invalidate the affected latest pages. The framework clips GPU drawing to the canvas bounds.

For the future world map, `MapPageStore` partitions tile histories into 32×32-tile region directories and keeps at most 256 region indexes open by default. It couples appends with page-cache invalidation. The benchmark keeps its existing flat history folder so earlier benchmark data remains usable. Derived LOD images are not persisted or Git-synced yet. Each zoomed-out pixel uses one deterministic source pixel instead of averaging a block; at LOD 4, one pixel represents an entire tile. Farther levels sample one tile from increasingly wide world areas and reduce page reads from 16,384 to 4,096, 1,024, then 256. The 128×128 page repeats those samples across larger cells; sample positions stay anchored to world coordinates. The horizontal suite measures page footprint, reads, bytes, latency, region reopen counts, and allocated index arrays at LOD 4–12 with 16- and 256-region caches. The storage reader uses index masks to find the layers covering requested pixels and issues positioned reads for their color bytes. The suite reports logical record bytes transferred; actual disk I/O still depends on filesystem and OS caching.

Each tile is 16×16 pixels with one byte per color. Every observation is the same layer type: a time stamp, a 256-bit coverage mask, and one color byte for each covered pixel. A first observation covers all pixels. Later observations usually cover only changed pixels. Historical reads walk layers from newest to oldest and skip a layer when newer layers already cover all its pixels.

Before an append, Palimpsest compares every covered pixel with the latest stored tile. Matching pixels are removed from ordinary layers; a layer with no changed pixels creates no record or segment. `TileLayer.full` is a full observation subject to that rule. `TileLayer.snapshot` explicitly keeps a complete layer even when every pixel is unchanged, for checkpointing. The distinction affects the append decision only; both use the same on-disk layer format.

Layers are appended in immutable, content-addressed `.pseg` segments under `config/palimpsest/benchmark/` in the Minecraft instance. Segments group records by tile, store epochs as per-tile deltas, and choose sparse position/color pairs, a coverage mask, or full colors for each layer. Each record describes its own length through its encoding and coverage. On reopening, Palimpsest verifies each segment's SHA-256 name, parses every record, then rebuilds its in-memory tile/time index. Writes seal a temporary file before an atomic rename and index only the new segment. **Delete earlier experimental benchmark `.pseg` files before opening this build**; they are incompatible with this format.

The in-memory index packs epochs, segment IDs, record positions, and coverage references into primitive arrays per tile. A one-pixel layer stores its pixel position directly; two to eight pixels fit in one packed side-array entry; a full layer uses a sentinel; larger masks use a separate side array. Tile histories dominated by large masks switch to inline masks when that uses less memory. A combined mask for every 64 layers can skip a whole group when newer layers already resolve all of its pixels. The GUI's **index arrays** figure counts those allocated arrays; it excludes object overhead, file channels, and the rest of the game heap. Reopen still verifies and scans all segments, so the readout is useful for comparing index experiments at large histories.

The benchmark uses reproducible random edits. It measures the storage prototype on your machine; it is not a gameplay performance result.
